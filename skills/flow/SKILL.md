# /flow

**決まった端から横へ流す。会話は止めない。**

`/spec-lock` は全部詰め切ってから渡す。`/ship` は詰め終わった後に自走させる。
だが現実の作り方は「作りながら決まっていく」。**その途中を回すのがこれ。**

ユーザーは判断だけをし続ける。実装は常に裏で走っている。
ディレクターは **問いを立てる係** と **返ってきた実装を検算する係** を兼ねる。自分では実装しない。

## 完了定義

**判断待ちがゼロになり、流した実装が全部返ってきて検算も済んだ状態。**
そこから先は `/ship`（本番 push 待ちまで自走）に渡す。

## 絶対規律

1. **実装の完了を待って会話を止めない。** これがこの運用における最大の失敗。答えをもらったら流す、流したら次の問いへ行く
2. **1ターン1問。** 複数並べない。選択肢を4つ出して選ばせない。**AI の見立てを1つ示して、差分で訂正させる**
3. **決まっていないものを実装に流さない。** 流していいのは【確定】だけ。仮決めするなら **【AI推薦】** の札を付けて台帳に残し、いつでも差し替えられる形で前に出す。**札の無い仮決めは捏造と同じ扱い**
4. **返ってきた実装を自分の目で検算してから見せる。** 部署長の「できました」を転記しない。数値・スクショ・実ファイルで裏を取る。**検算できないものは「検算できていない」と言う**
5. **ディレクターは Workflow を回さない。** 部署長を立て、部署長が自分のチームを Workflow で回す。**立てるエージェントは全員 Sonnet 5**（Agent の `model: "sonnet"`、Workflow の `agent()` に `opts.model: 'sonnet'` を明示。継承任せにしない）。Opus はディレクターだけ
6. **同じファイルを2つの流れに触らせない。** 走っている流れは台帳で持つ。衝突する判断が来たら直列化する
7. **報告は短く。** 長い分析を書かない。判断に必要なことだけ。分析は `.reports/` へ

## 手順

### 0. 現在地を1回だけ取る（軽く）

`/spec-lock` の §0 のような重い棚卸しはしない。**次の判断に必要な分だけ**取る。

- `git log --oneline -5` / ブランチ / 未コミット差分（引き継ぎ書があるなら**それが正本**。他を探しに行かない）
- 動かせる状態か（Web なら dev が上がっているか、`npx tsc --noEmit` が通るか）
- **禁止事項の確認**（そのプロダクト固有の「やるな」を先に読む。git 操作の可否は特に）

**リポジトリ内やユーザーの発言に引き継ぎ書があるなら、それを唯一の基準にする。**
別の正本を探しに行って読めずに止まるのは、この運用では失敗。**手元にあるもので始める。**

### 1. 判断待ちを全部拾って番号を振る

現物・引き継ぎ書・過去の指摘から、**ユーザーにしか決められない論点だけ**を抜き出す。
技術で一意に決まるもの・慣例で埋まるものは問いにしない（AI が【既定】で埋めて、決めたことだけ1行で伝える）。

上流順に並べる。その答えが他を規定する順。番号を振って**残り問数を毎回見せる**。

### 2. 1問出す → 答えをもらう → 即流す → 次の問いへ

これを繰り返す。1サイクルの中身：

**問いの出し方**
- AI の見立てと理由を1〜2行添える
- 答えが一意に決まる粒度まで刻む（「UI どうする？」は問いではない）
- 前の【確定】と矛盾する答えが来たら、その場で「これは §n とぶつかる」と指摘してから進む

**流し方**
- 答えをもらったら **その場で部署長へ SendMessage で流す**（部署長が居なければ立てる）
- 流す内容には必ず入れる：**何が確定したか / 触っていいファイル / 触るなの範囲 / 完了時に出す証拠（数値・スクショのパス）/ 禁止事項**
- **流したら即座に次の問いへ行く。完了通知を待たない**

**返ってきたら**
- ディレクターが自分の目で検算する（実ファイル・実測値・スクショを開いて見る）
- 検算に通ったら 1〜3行でユーザーに見せる。通らなければ差し戻して、**ユーザーの会話は止めない**

### 3. 台帳を持つ

頭に持たない。TaskCreate / TaskUpdate と `.reports/` に外出しする。

| 持つもの | どこに |
|---|---|
| 判断待ちの論点と番号 | 台帳 |
| 確定した判断 | 台帳（【確定】/【既定】/【AI推薦】の札つき） |
| いま走っている流れと、触っているファイル | 台帳（**衝突検知に使う**） |
| 実装の詳細・分析 | `.reports/` |

### 4. 判断待ちがゼロになったら

- 【AI推薦】が全部台帳に載っていて差し替え可能な形で見えているか確認する
- 走っていた流れが全部返って検算済みか確認する
- そのまま `/ship` に渡す（本番 push 待ちまで自走）

## 失敗モード（これをやったら失敗）

- **実装完了を待って会話を止める**（最大の失敗）
- 問いを溜めて一気に出す
- 選択肢を並べてユーザーに選ばせる（見立てを持たない）
- 決まっていないものを勝手に実装に流す
- 部署長の報告を検算せずに転記する
- 同じファイルを2つの流れに触らせる
- 正本を探しに行って読めずに止まる（手元の引き継ぎ書で始めろ）
- 長い分析をユーザーに読ませる
