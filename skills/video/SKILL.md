# /video

動画を ffmpeg でフレーム分解し、Claude（自分）が画像として読んで中身を解析するスキル。
画面収録した UI アニメーションや操作フローの挙動を、フレーム単位で正確に読み取るのが目的。

## 前提確認

最初に ffmpeg の存在を確認する。

```bash
which ffmpeg
```

無ければ `brew install ffmpeg` を案内して停止する（勝手に install しない）。

## 手順

### 1. 対象動画の特定

- **引数（絶対パス）が渡された場合**: そのファイルを対象にする。
- **引数なしの場合**: `~/スクリーンショット/` 内の最新 `.mov` / `.mp4` を自動検出する。

```bash
ls -t ~/スクリーンショット/*.mov ~/スクリーンショット/*.mp4 2>/dev/null | head -1
```

複数候補があって判断に迷う時だけ `AskUserQuestion` で確認する。原則は最新1件を黙って使う。

### 2. 作業フォルダ作成 + 動画コピー

パスにスペースや日本語が含まれるとコマンドが壊れやすいので、**作業フォルダ内に `source.mov` としてコピーしてから**処理する。
作業フォルダは毎回クリーンに作り直す。

```bash
WORK="<動画のあるディレクトリ>/_frames_work"
rm -rf "$WORK" && mkdir -p "$WORK/animation_frames"
cp "<元の動画パス>" "$WORK/source.mov"
```

### 3. 圧縮（軽量化）

```bash
cd "$WORK" && ffmpeg -hide_banner -loglevel error \
  -i source.mov -vf "scale=1170:-2" -r 30 compressed.mp4
```

★ **`scale=幅:-2` を使う（`-1` ではない）**。H.264 は幅・高さとも偶数を要求するため、`-1` だと高さが奇数になってエンコードが落ちることがある。`-2` は「アスペクト比維持＋偶数に丸める」指定。
★ 幅 1170 は iPhone 実機相当。重い動画なら 780 など下げてよい。

### 4. フレーム化

```bash
cd "$WORK" && ffmpeg -hide_banner -loglevel error \
  -i compressed.mp4 -vf "fps=5,scale=1170:-2" animation_frames/frame_%03d.jpg
```

★ `fps=5` は1秒5枚。動きが速い動画は `fps=10`、ゆっくりなら `fps=2` に調整する。
★ 動画尺は `ffprobe -hide_banner -loglevel error -show_entries format=duration -of csv=p=0 compressed.mp4` で確認できる。尺 × fps ≒ 総フレーム数。

### 5. コンタクトシート（一覧）生成

```bash
cd "$WORK" && ffmpeg -hide_banner -loglevel error \
  -i compressed.mp4 -vf "fps=5,scale=390:-2,tile=5x6" animation_contact_sheet_%03d.jpg
```

★ `tile=5x6` は1枚に30コマ。総フレームが30を超えると `_001`, `_002`, ... と複数枚に分かれる。
★ 縦長動画を5x6に詰めると各コマの文字は潰れる。一覧は「全体の流れ・転換点の当たりをつける」用途と割り切る。

### 6. 全体像の把握（コンタクトシートを Read）

生成したコンタクトシート（`animation_contact_sheet_*.jpg`）を **Read ツールで全部読む**。
ここでアニメーションの大まかな流れ・状態遷移・転換点（どのコマで何が変わるか）の当たりをつける。

### 7. 個別フレームで精読（必要に応じて）

転換点付近の `animation_frames/frame_NNN.jpg` を**時系列で複数枚 Read** して、細部を正確に読み取る。

- 開始 → 中盤 → 終盤を等間隔でサンプリングするのが基本（例: 001 / 018 / 030 / 042 / 055 / 071）。
- 文字モーフィングや状態遷移は、変化が起きているコマの前後を細かく追う。
- Read は複数ファイルを**1メッセージ内で並列**に投げると速い。

### 8. 解析結果を報告

読み取った内容を構造化して報告する。最低限以下を含める:

- **成果物の場所**（作業フォルダの絶対パス、各ファイルの役割）
- **動画尺・fps・総フレーム数**
- **時系列テーブル**（frame / 時刻 / その時点の状態）
- **何のアニメーション/操作か**の解釈

## 調整パラメータまとめ

| 項目 | デフォルト | 変える時 |
|---|---|---|
| 圧縮幅 | 1170 | 重い動画は 780 / 540 に下げる |
| fps | 5 | 速い動き→10、ゆっくり→2 |
| タイル | 5x6 | 長尺で枚数を減らしたい→6x8 等 |

## 禁止 / 注意

- 元動画ファイルは絶対に削除・上書きしない（必ずコピーして作業する）。
- `scale=...:-1` を使わない（偶数制約で落ちる）。`-2` を使う。
- 日本語・スペース入りパスは必ずダブルクォートで囲む。
- ffmpeg が無い時に勝手に `brew install` しない（案内のみ）。
