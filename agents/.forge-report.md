## 設計方針（この18本に共通する骨）

各ファイルは次の構成で統一:
`正体` / `場所` / `構成` / `ビルド・起動` / `固有の地雷` / `現在地と残タスク` / `着手プロトコル` / `worker への必須文` / `verifier への必須文` / `未確定事項`

- **推測でビルドコマンドや scheme 名を書いていない。** 確認できなかったものは「未確認。推測で使うな」と明記
- **全 lead が「自分ではコードを書かず Workflow で worker/verifier を編成する」部署長規律を持つ**
- **全 lead が「commit・プレビューまで自動、本番 push はユーザーの一言」の境界を持つ**
