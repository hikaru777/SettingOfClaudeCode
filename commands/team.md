# /team — エージェントチームを起動する

TeamCreate でエージェントチームを作成し、タスクを並行実行する。

## 引数

- 任意のテキスト: 実行したいタスクの説明（省略時は聞く）

## チーム構成

引数の内容に応じて最適なチーム構成を自動で決定する。基本パターン：

### 調査→実装パターン（デフォルト）
```
- investigator: コードベース調査・設計方針の策定
- implementer-1: 実装担当（メイン）
- implementer-2: 実装担当（サブ、必要な場合のみ）
- reviewer: コードレビュー・品質チェック
```

### 調査のみパターン（「調べて」「分析して」等の場合）
```
- researcher-1: 調査担当A
- researcher-2: 調査担当B
- summarizer: 結果まとめ
```

## 手順

### 1. タスクを確認する

引数がなければユーザーに「何をやりたい？」と聞く。

### 2. チームを作成する

TeamCreate で上記の構成に基づきチームメンバーを作成する。

### 3. 通信ルールを設定する

以下の通信ルールを全メンバーに徹底させる：

- investigator は調査完了時に implementer に SendMessage で結果を共有
- implementer はファイル1つ編集完了ごとに reviewer に SendMessage で通知
- reviewer は問題発見時に implementer に SendMessage で修正指示
- 全メンバーはスタックしたらリーダーに SendMessage で報告
- リーダー（自分）は実装せず、調整・意思決定に徹する

### 4. タスクの分割と割り当て

- タスクを各メンバーの役割に沿って分割
- 同じファイルを複数メンバーが触らないようにファイル割り当てを明示
- 各メンバーに SendMessage でタスクと担当ファイルを通知

### 5. 進捗管理

- 各メンバーの進捗を監視
- スタックしているメンバーがいれば介入
- 全メンバー完了後、reviewer の結果を確認
- 問題があれば修正指示を出す
- 完了したらユーザーに結果を報告

## 注意事項

- メンバー数は最大4名（リーダー除く）。それ以上は収穫逓減
- 各メンバーの担当ファイルは重複させない
- リーダーは実装しない。調整と意思決定のみ
- メンバーがスタックしたら新しいメンバーで再開させる
