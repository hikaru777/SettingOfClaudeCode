# /note-factory — トレンドリサーチ → 深掘り → note記事生成パイプライン

トレンドと人々の疑問を収集し、深掘りして特定の人に刺さるnote記事を自動生成する。
5%だけ人間の判断（下書きレビュー）を入れて、質の高い記事を作る。

プロジェクトディレクトリ: `~/App/NoteFactory/`
記事保存先: `~/Documents/輝/notes/`（ここに .md として積み重ねていく）

## 引数

- 引数なし: トレンドを自動検出してリサーチ
- キーワード指定（例: `Claude Code`, `AI副業`）: そのテーマでリサーチ

## 手順

### Step 1: リサーチ — トレンド・疑問を収集

WebSearchツールを使って以下を調査する：

1. **トレンド収集**: 直近で検索ボリュームが急上昇しているキーワード、バズっている投稿のテーマを収集
2. **疑問収集**: 「〜とは」「〜 やり方」など疑問系クエリ、Q&Aサイトで回答が不足している質問を収集
3. **競合チェック**: 各テーマの既存コンテンツの質と量をチェック

引数でキーワードが指定されていれば、そのキーワードに関連するトレンド・疑問に絞ってリサーチする。

以下の基準で3〜5テーマを選定する：
- 検索需要がある（★★★）
- 既存コンテンツが弱い（★★★）
- 具体的な悩み・疑問がある（★★）
- 有料noteとして成立する深さがある（★★）
- タイムリーさ（★）

リサーチ結果を `~/App/NoteFactory/data/research/YYYY-MM-DD_research.json` に保存する。

### Step 2: 分析・深掘り — ターゲット特定＋構成設計

Step 1のリサーチ結果を読み込み、以下を行う：

1. **テーマ最終選定**: 3〜5テーマから「需要 × 競合の弱さ × 有料成立度」で最強の1テーマを選ぶ
2. **ターゲット深掘り**: 以下5レベルで具体化する
   - 属性（年齢、職業、収入帯）
   - 状況（今どんな状況か）
   - 感情（何に焦り、何を恐れているか）
   - 行動（過去に何を試して失敗したか）
   - 欲求（本当は何が欲しいか — 深層欲求）
3. **切り口設計**: 1行目のフック案を5つ作成（常識否定、数字インパクト、疑問提起、暴露、共感）
4. **記事構成案**: タイトル3案、無料/有料パートの構成、想定文字数・価格を設計

分析結果を `~/App/NoteFactory/data/drafts/YYYY-MM-DD_analysis.json` に保存する。

### Step 3: 記事執筆 — note記事を生成＋品質採点

Step 2の分析・構成案をもとに、note記事を執筆する。

**執筆ルール:**
- 1行目で読者のスクロールを止めるフックを書く
- 一文60文字以内、専門用語は噛み砕く
- 体験談・具体例を必ず入れる
- 読者に語りかける口調

**構成:**
- 【無料パート】導入(300-500字) → 本文セクション1-2(各500-1000字) → 有料への橋渡し(200-300字)
- 【有料パート】核心の解決策(1000-2000字) → 実践手順(500-1000字) → まとめ(300-500字)

**品質スコア自己採点（10項目、平均7.0以上で合格）:**
1. フックの強さ
2. ターゲット明確性
3. 有益性
4. 具体性
5. 読みやすさ
6. オリジナリティ
7. 感情の動き
8. 有料価値
9. 行動喚起
10. タイトル力

7.0未満の場合は書き直す（最大2回リトライ、それでもダメなら棄却）。

記事は最初から `~/Documents/輝/notes/YYYY-MM-DD_タイトルスラッグ.md` に直接保存する。ファイル名の日本語タイトル部分は短く要約したものにする（例: `2026-03-26_AI副業の始め方.md`）。

### Step 4: 下書きレビュー（5%人間パート）

記事が完成したら、ユーザーに下書きを提示する。記事はすでに `~/Documents/輝/notes/` に保存済み。

表示する内容：
- タイトル
- 品質スコア（10項目 + 平均）
- 記事の冒頭300文字のプレビュー
- 記事全文のファイルパス

ユーザーに判断を仰ぐ：
- **OK** → noteに自動投稿する。以下のコマンドをBashで実行：
  ```
  python3 ~/App/NoteFactory/scripts/publish.py "記事ファイルパス"
  ```
  投稿完了したらURLを伝える。
  ユーザーが「下書きで」と言った場合は `--draft` フラグを付ける。
- **NG** → 理由を聞いて、修正指示があれば `~/Documents/輝/notes/` 内のファイルを直接書き直す
- **編集** → ユーザーの指示に従って該当ファイルを修正し、再度レビューに回す

### 有料記事の書き方
記事本文中に有料ラインを設ける場合、以下の記述を入れる：
```
> **ここから有料パートです（500円）**
```
投稿スクリプトがこれを自動的に `<pay>` タグに変換する。
frontmatterの `price` が100以上なら有料記事として投稿される。

記事のMarkdownファイルには以下のfrontmatterを付ける：
```markdown
---
title: "記事タイトル"
date: YYYY-MM-DD
target: "ターゲット層"
price: 0 or 100-10000
quality_score: 平均スコア
status: draft
tags: [関連タグ]
---
```

## ナレッジファイル

`~/App/NoteFactory/knowledge/profile.md` にキャラ設定・NGワードがある。執筆時に参照すること。

## 注意事項

- 嘘の数字やデータは使わない
- 「簡単に稼げる」系の煽りはNG
- 情報商材っぽいトーンは避ける
- 無料部分だけでも価値がある内容にする
- 各Stepの完了時に簡潔に進捗を伝える
